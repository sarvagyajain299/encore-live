# PR: Phase 7, performance (Core Web Vitals)

**Branch:** `feature/phase-7-performance` → `main`

## Summary
Baseline measured first, then optimised:
- page cache (with a bug fix found by measuring) and purging on stock/status changes
- WooCommerce/jQuery/emoji/block-library trimming
- inlined critical CSS
- a self-hosted font
- WebP and right-sized images

Lighthouse mobile went to 100 on all three audited pages, and TTFB dropped from ~1 s to ~10 ms. Full report: `docs/PERFORMANCE.md`.

## Changes
- **Theme:**
  - `inc/performance.php` (asset trimming, critical CSS, async CSS, font preload, emoji, WebP)
  - `assets/css/critical.css` + `main.css` split
  - `assets/fonts/` (Archivo, OFL licence included)
  - `encore-card-sm` image size
- **Plugin:** `src/Performance/PageCachePurge.php`. `PlaceholderImage` now writes WebP.
- **Config:**
  - `WP_CACHE` in `.env` / `docker-compose.yml`
  - `scripts/cache-config.php`
  - home meta in `seo-config.php`
- **Tooling:** `scripts/lighthouse.ps1`. The SEO and Lighthouse scripts now clear the page cache when toggling `blog_public`.
- **Reports:** `docs/perf/before/`, `docs/perf/after/`, `docs/PERFORMANCE.md`.

## Test steps
1. Add `WP_CACHE=true` to `.env`, run `.\scripts\encore.ps1 up`, then `.\scripts\encore.ps1 install`.
2. Logged out, load `/shows/` twice. View Source ends with `<!-- Cached page generated by WP-Super-Cache … -->`.

## Risks
- **Cache staleness for changes made outside WordPress hooks.** The 30 min TTL bounds it.
- **Critical CSS drift.** New above-the-fold components must go in `critical.css`.
- **Production config.** Nginx should serve supercache files directly. Rules are in `docs/PERFORMANCE.md`; this belongs to the VPS deploy prompt.
